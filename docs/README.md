# 프로젝트 문서

프로젝트에서 사용하는 설계 및 운영 문서를 한곳에서 관리합니다.

| 문서 | 설명 | 상태 |
| --- | --- | --- |
| [에이전트 작업 지침](../AGENTS.md) | 브랜치, 커밋, 검증, 보안 및 작업 완료 규칙 | 적용 중 |
| [서비스 기획서](./product-spec.md) | 서비스 목표, 확정 MVP, 제외 범위와 팀 담당 | MVP 기획 확정안 |
| [API 명세서](./api-spec.md) | Gateway 기준 API, 권한, 요청·응답 및 오류 코드 | MVP 설계 초안 |
| [ERD](./erd.md) | 서비스별 데이터 소유권, 논리 관계, 제약조건 및 이벤트 | MVP 논리 설계 초안 |

## 문서 관리 규칙

- 설계가 변경되면 관련 코드와 문서를 같은 Pull Request에서 함께 수정합니다.
- 구현 전 URL과 요청·응답은 설계 초안으로 관리합니다.
- 구현 후에는 Swagger UI의 실제 Method, URL, Request, Response 및 상태 코드와 대조합니다.
- 검증이 끝난 문서는 상태를 `검증 완료`로 변경하고 검증 날짜를 기록합니다.
- 문서만 변경하는 커밋은 `docs: 한국어 제목` 형식을 사용합니다.
